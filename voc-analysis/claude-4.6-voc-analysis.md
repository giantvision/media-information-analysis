# 基于Claude-4.6模型的VOC实体抽取/主题聚合方案调研

## 需求描述
我我一个游戏运营策划，目前正在针对游《信长之野望 真战》游戏进行用户行为研究，我需要从大量的用户原声数据中抽取提炼玩家的反馈信息和意图，通过了解玩家的诉求来发现问题、改进和优化游戏的体验，请你先针对《信长之野望》系列的SLG游戏的特点，搜索网上大量的相关游戏的知识或者该游戏的不同系统的知识，然后帮我分析整理一套系统化的分析框架，来洞察用户行为、挖掘用户原生信息中的价值。我们目前正在尝试的一个技术路线说明：我们针对收集获取到的大量的用户原声(包括公司游戏内的数据、外部公共域信息)，目前已经使用了AI LLM 对不同的用户原生进行了小结归纳，目前每一条用户原生数据都有一些抽取出来的重要实体和一条总结性的话题描述，后续我们想基于每条数据抽取出来的关键实体信息和话题描述，从不同的层级对不同的数据点进行向上的话题聚合，来方便后续的分析，我们想要一个具有严谨层次结构的从实体到最终不同层级分析唯独的框架大纲，能尽量涵盖当前SLG 游戏的大部份核心的用户原声信息。你可以现在GitHub上检索看看是否有类似的开源项目可以借鉴，然后基于上面的详细的需求描述进行深入的技术分析，并研究后续的落地方法。

## 框架核心设计思路

现在我有了足够的信息来构建一套全面的分析框架。让我来整理这份完整的文档。这是一个完整的分析框架文档，我将直接创建为 Markdown 文件。框架文档已生成，以下是整体思路的简要说明：

### 四层金字塔结构

框架围绕你已有的"实体 + 话题描述"数据，设计了严谨的四层向上聚合路径：

**Layer 0 → 原始实体层**（已有）：7类实体类型的定义（系统/对象/行为/属性/情感/比较/诉求），确保实体归类有明确语义边界。

**Layer 1 → 微话题层**（43个具体话题）：覆盖战斗(F)、养成(G)、内政(I)、大地图(M)、社交(S)、付费(P)、新手(N)、内容(C)、技术(T) 九大系统模块。每个微话题都有ID、名称和典型关键词，可直接作为LLM分类的标签体系。

**Layer 2 → 中话题层**（18个维度）：按"体验维度"而非系统归并，形成可做版本前后对比的分析单元，例如"养成成本与价值感"横跨G-01/02/05/06四个微话题。

**Layer 3 → 宏话题层**（6个运营议题）：对应运营策划最关心的核心命题，直接驱动优先级排序。

**Layer 4 → 战略洞察层**（5个命题）：聚焦产品定位层的决策，如"公平策略承诺兑现度"这类跨系统的战略性问题。

### 技术落地建议

你已有实体+描述的中间数据，后续关键步骤是**Layer 1 分类**，三种方案各有优势：
- **LLM Zero-shot分类**最推荐，能捕捉语义意图而非关键词表面匹配，直接把微话题分类树作为Prompt输入，精度高且可解释；
- **BERTopic + HDBSCAN**适合定期探索框架盲点，发现新版本出现的全新话题类型，BERTopic本身支持层级聚类可视化，方便将聚类结果与框架对齐；
- **LLooM这类LLM驱动的概念归纳工具**适合在框架初建阶段，从底层数据中自动涌现出话题分类体系，适合你们后续框架迭代时使用。

框架还包含**正交分析轴**（情感极性、用户生命周期、玩家类型、反馈来源），让同一条数据可以从多个维度切片，避免只做单一话题分类。

## 一、框架设计背景与目标

### 1.1 游戏品类定位理解

《信长之野望 真战》是一款 **SLG × RPG 融合型策略手游**，由《三国志·战略版》原班团队打造，具备以下独特性：

| 维度 | 特征描述 |
|------|----------|
| 核心玩法 | 大地图占领 + 内政建设 + 武将养成 + 家族势力体系 |
| 差异化系统 | RPG六大能力成长、家宰/奉行内政体系、直接交涉/策反系统 |
| 竞争定位 | 公平策略（零氪可赛季高排名）、考究历史、真实战场 |
| 用户群体 | 历史向策略硬核玩家 + 率土/三战迁移用户 + 战国IP粉丝 |

### 1.2 框架设计目标

本框架服务于以下核心目标：

1. **结构化捕获**：将散乱的玩家原声数据映射到有序的知识体系
2. **分层聚合**：支持从最细粒度的实体，逐级向上聚合到战略维度
3. **多向分析**：支持按系统、按情感、按用户阶段、按优先级等多维切分
4. **可落地执行**：直接衔接已有的"实体抽取 + 话题描述"数据结构

## 三、四层分析框架大纲（核心交付物）

### Layer 0：原始实体层（Raw Entity Layer）

**来源**：LLM从用户原声中抽取的关键实体和话题描述（已有数据）

**实体类型定义**：

| 实体类型 | 说明 | 示例 |
|----------|------|------|
| **系统实体** | 游戏系统/功能模块名称 | 武将养成、家宰体系、大地图 |
| **对象实体** | 具体的游戏内对象 | 织田信长、骑马兵、战法「威风」 |
| **行为实体** | 玩家动作/操作行为 | 征兵、行军、策反、联盟战 |
| **属性实体** | 数值/状态/特征 | 战力差距、资源产出、兵种克制 |
| **情感实体** | 情绪/态度词 | 不公平、好玩、期待、失望 |
| **比较实体** | 与其他游戏/版本的对比 | 比三国战略版、原版单机 |
| **诉求实体** | 明确的需求/建议 | 希望加入、希望修复、建议调整 |

**话题描述要素**：
- 情感极性（正向/负向/中性/建议型）
- 核心诉求意图（见Layer 1分类）
- 关联系统（见2.1系统分类）
- 用户阶段（新手/成长期/成熟期/流失前）

## 四、分析维度扩展：正交分析轴

> 上述四层框架是"内容维度"的纵向结构，还需要以下"正交轴"进行横向切割分析。

### 4.1 情感极性维度

```
正向反馈（好评/赞赏）
  └── 功能亮点 / 超出预期 / 强烈推荐

建议型反馈（中性/优化建议）
  └── 希望改进 / 功能缺失 / 体验摩擦

负向反馈（投诉/不满）
  └── 严重影响体验 / 导致流失意向 / 负面传播

比较型反馈（与竞品/历史版本对比）
  └── 优于竞品 / 劣于竞品 / 期待对标功能
```

### 4.2 用户生命周期维度

```
注册/安装阶段（0-1天）
  └── 主要话题：引导、上手、第一印象

新手成长期（1-14天）
  └── 主要话题：建设节奏、战斗入门、新手保护

活跃成长期（15-60天）
  └── 主要话题：养成投入、联盟融入、竞争体验

核心玩家期（60天+）
  └── 主要话题：深度策略、顶端竞争、社交维系

流失风险期
  └── 主要话题：目标感缺失、被碾压、内容枯竭

回流玩家
  └── 主要话题：新内容评价、改善感知
```

#### 方案二：BERTopic层级聚类（推荐用于发现新话题）

**适用场景**：当用户反馈出现大量框架外的新话题时，通过BERTopic进行底层聚类，发现框架未覆盖的盲点。

**技术栈**：
```python
# 推荐技术组合
from bertopic import BERTopic
from sentence_transformers import SentenceTransformer

# 使用多语言模型（中日文支持）
embedding_model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

# 构建层级话题
topic_model = BERTopic(
    embedding_model=embedding_model,
    nr_topics="auto",
    calculate_probabilities=True
)

# 层级聚合
hierarchical_topics = topic_model.hierarchical_topics(docs)
topic_model.visualize_hierarchy(hierarchical_topics=hierarchical_topics)
```

**与LLM结合的最佳实践**（参考GitHub用法）：
- BERTopic负责无监督聚类，发现话题结构
- LLM（GPT-4/Claude）负责为每个聚类生成可读的话题标签
- 人工Review确认与框架的映射关系

### 5.4 聚合分析引擎设计

#### 时间维度聚合（话题趋势）
```sql
-- 按周统计各微话题的声量与情感分布
SELECT 
  week_tag,
  layer1_primary,
  COUNT(*) as volume,
  SUM(CASE WHEN sentiment='positive' THEN 1 ELSE 0 END) / COUNT(*) as positive_rate
FROM user_feedback
GROUP BY week_tag, layer1_primary
ORDER BY week_tag, volume DESC;
```

#### 紧急度优先级矩阵
```
优先级 = 声量权重 × 情感负向强度 × 用户层级权重

高优先级（立即处理）：
  - 技术Bug类 + 大量负向 + 核心用户
  - 新手流失关键节点 + 快速增长趋势

中优先级（版本规划）：
  - 单一系统体验优化 + 稳定负向声量

低优先级（长期优化）：
  - 内容丰富度需求 + 小众用户
```
